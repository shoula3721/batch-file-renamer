Batch File Renamer · Instructions

Version v37.21.beta3 · Preview first · Back up before renaming · Restore anytime

Quick start

  1. Click “Add” to choose files, or drag files / folders into the window (Ctrl+O adds files).
  2. Set the rules on the left tabs “Entire name / Replace / Add / Remove / Metadata”.
  3. Check the “Shot time” and “Preview” columns, then click “Start renaming” once everything looks right.
  4. Before execution a JSON backup is written, then files are renamed in two stages through temporary names; failures roll back automatically.
  5. To undo, press Ctrl+Z or use “Edit → One-click restore”.

Replacement and regex

  • Plain replacement is case sensitive by default; turn off “Case sensitive” or tick “Replace first match only”.
  • With “Use regular expression” enabled, capture groups are supported: ^IMG_(\d+) → photo_$1.
  • You can also write \1 or ${name}; an invalid regex turns the field red below the input and preview will not run.
  • “Include extension” decides whether the extension is part of the replacement scope.

Shot time and metadata

  • Images use EXIF DateTimeOriginal; MP4/MOV use the mvhd creation time (UTC).
  • If none is found, the file modified time is used instead and marked with a gray ⓘ in the list; hover to see the source and raw value.
  • Date source, date format (including custom strftime), and time zone are set on the “Metadata” tab.
  • Results are cached; the cache is invalidated automatically when a file changes outside the app. Right-click to choose “Re-read shot time”.
  • View → Sort by shot time, or click the “Shot time” header to toggle ascending / descending.

Filtering, sorting, and numbering

  • The filter bar at the top lets you pick extensions or type several, e.g. mp4;mkv; the status bar shows Filter 12/55.
  • With a filter active, renaming asks for confirmation and only processes the filtered files.
  • The number # always follows the current list order; sorting or moving items up / down changes the numbers.

Backup, undo, and restore

  • Every rename / restore first writes a JSON backup to %APPDATA%\批量文件改名\backups; up to 100 batches are kept.
  • All renames first change to a temporary name in the same folder (.~br_*.tmp) and then to the target name; existing files are never overwritten.
  • Ctrl+Z, the context menu, or the result dialog can undo the most recent rename.
  • “File → Backup manager” or “Edit → One-click restore” lists all batches and restores the ones you select; taken original paths are skipped by default, or given an automatic (1); overwriting is never offered.
  • If the app exits unexpectedly, reopening it offers to recover the unfinished batch.

Preset import / export

An exported .bfr.json contains all rules, metadata settings, filter extensions, and sort order, but not the file list, so it can be reused directly on another computer or in another folder. Window size, tabs, and recent presets are remembered automatically.

FAQ

Why does “Status” show unchanged after renaming?
After a successful rename the list re-previews with the new file name; if the current rule would not change that new name, it shows “Unchanged”, while the “Result” column still records “Succeeded”.

Why does the preview column show (1)?
The target name conflicts with a file already in the folder and “Resolve name conflicts automatically” is on. Execution also avoids files with the same name.

What if a file is locked or read-only?
The app retries 3 times; if it still fails, that file is marked as failed and left untouched while the remaining files continue. The result dialog shows the reason.

What happens if the process is killed halfway through?
Restarting the app offers to recover the unfinished batch, using the temporary names or new names recorded in the backup. Do not delete the backup JSON manually.

Why does SmartScreen appear on the first run of the exe?
It is the normal prompt for an unsigned program; once you have verified the source you can choose “Run anyway”. Code signing is recommended for official distribution.
