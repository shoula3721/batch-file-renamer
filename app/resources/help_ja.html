一括ファイル名変更 · 使い方

バージョン v37.21.beta3 · プレビュー優先 · バックアップ後に改名 · いつでも復元

クイックスタート

  1. 「追加」をクリックしてファイルを選ぶか、ファイル／フォルダーをウィンドウにドラッグします（Ctrl+O でファイルを追加）。
  2. 左側の「全体 / 置換 / 追加 / 削除 / メタデータ」タブで規則を設定します。
  3. 「撮影日時」「プレビュー」列を確認し、問題がなければ「改名を開始」をクリックします。
  4. 実行前に JSON バックアップを書き込み、一時名を経て 2 段階で改名します。失敗時は自動でロールバックします。
  5. 元に戻すときは Ctrl+Z、または「編集 → ワンクリック復元」を使います。

命名規則

記号意味例

#連番。リストの現在の順序で生成写真_### → 写真_001
{date}日付。形式はメタデータタブで設定2026-11-21
{time}時刻 HHMMSS214000
{datetime}日時2026-11-21_214000
{name}元のファイル名（拡張子なし）IMG_001
{ext}拡張子JPG
{size}ファイルサイズ（バイト。{size:05d} も指定可）04823
{mtime} / {ctime}ファイル更新時刻 / 作成時刻2026-11-21_203102

規則内で日付にカスタム形式も指定できます（例：{date:%Y%m%d}）。\*、\#、\{ はリテラル文字を出力します。

置換と正規表現

  • 通常の置換は既定で大文字と小文字を区別します。「大文字と小文字を区別」をオフにするか、「最初の一致のみ置換」にチェックできます。
  • 「正規表現を使用」にチェックするとキャプチャグループが使えます：^IMG_(\d+) → 写真_$1。
  • \1 や ${name} も書けます。正規表現が不正な場合は入力欄の下が赤くなり、プレビューは実行されません。
  • 「拡張子を含める」は、置換範囲に拡張子部分を含めるかどうかを決めます。

撮影日時とメタデータ

  • 画像は EXIF DateTimeOriginal、MP4/MOV は mvhd の作成時刻（UTC）を読み取ります。
  • 見つからない場合はファイルの更新時刻に自動でフォールバックし、リストに灰色の ⓘ で表示します。ホバーすると取得元と元データを確認できます。
  • 日付の取得元、日付フォーマット（カスタム strftime を含む）、タイムゾーンは「メタデータ」タブで設定します。
  • 読み取り結果はキャッシュされます。外部でファイルが変更されると自動的に無効になります。右クリックで「撮影日時を再読み取り」を選べます。
  • 表示 → 撮影日時で並べ替え、または「撮影日時」列のヘッダーをクリックして昇順 / 降順を切り替えます。

フィルター・並べ替え・連番

  • 上部のフィルターバーで拡張子を選ぶか、mp4;mkv のように複数入力できます。ステータスバーには フィルター 12/55 と表示されます。
  • フィルター適用中に改名を実行すると確認を求められ、絞り込まれたファイルのみ処理します。
  • 連番 # は常にリストの現在の順序で生成されます。並べ替えや上下移動で番号が変わります。

バックアップ・元に戻す・復元

  • 改名 / 復元のたびに JSON バックアップを %APPDATA%\批量文件改名\backups に書き込みます。保持するバッチは最大 100 件です。
  • すべての改名は、まず同じフォルダー内の一時名（.~br_*.tmp）に変更し、その後で目的の名前にします。既存ファイルは上書きしません。
  • Ctrl+Z、右クリックメニュー、または結果ダイアログから直前の改名を元に戻せます。
  • 「ファイル → バックアップ管理」または「編集 → ワンクリック復元」で全バッチを確認し、選んだものだけ復元できます。 元の場所が使用中の場合は既定でスキップし、自動で (1) を付けることもできます。上書きは行いません。
  • アプリが異常終了した後に再起動すると、未完了のバッチの復元を促します。

プリセットの読み込み / 書き出し

書き出した .bfr.json には、すべての規則、メタデータ設定、フィルター拡張子、並べ替え方法が含まれますが、ファイルリストは含まれません。 そのため、別のパソコンや別のフォルダーでもそのまま再利用できます。ウィンドウサイズ、タブ、最近のプリセットは自動的に記憶されます。

よくある質問

実行後に「状態」が未変更になるのはなぜですか？
改名に成功すると、リストは新しいファイル名で再プレビューされます。現在の規則でその新しい名前に変化がない場合は「未変更」と表示されますが、 「結果」列には「成功」が残ります。

プレビュー列に (1) が表示されるのはなぜですか？
目的の名前がフォルダー内の既存ファイルと衝突し、「名前の衝突を自動解決」が有効になっています。実行時も同名のファイルは避けます。

ファイルが使用中 / 読み取り専用の場合は？
アプリは 3 回再試行します。それでも失敗した場合は、そのファイルを失敗として元のまま残し、残りのファイルの処理を続けます。理由は結果ダイアログで確認できます。

改名の途中でプロセスを強制終了した場合は？
アプリを再起動すると未完了バッチの復元を促し、バックアップにある一時名または新しい名前で復元します。バックアップの JSON は手動で削除しないでください。

exe の初回実行で SmartScreen が表示されるのはなぜですか？
署名されていないプログラムでは通常表示される警告です。提供元を確認したうえで「それでも実行」を選べます。正式配布時はコード署名を推奨します。

バックアップフォルダー：%APPDATA%\批量文件改名\backups。このヘルプはオフラインの内容で、ネットワークにはアクセスしません。
